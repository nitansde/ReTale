# Preset compatibility field mapping

This table documents the actual ChatBook implementation. It records what the current code stores, exports, applies, degrades, previews, or preserves today.

## Storage buckets and reference points

- top-level numeric and sampler controls live in `preset.runtimeSampler`
- reset and formatting strings live in `preset.promptTemplate`
- transport and route flags live in `preset.transport`
- preserved scalar metadata lives in `preset.preservedFields`
- prompt entries live in `preset.promptRules`
- prompt-order lists live in `preset.promptOrderLists`
- embedded regexes live in `preset.embeddedRegexes`
- unknown root and extension data lives in `preset.passthrough.root` and `preset.passthrough.extensions`
- prompt-entry passthrough lives in `preset.passthrough.unknownPromptFields`
- legacy flat prompt aliases live in `preset.passthrough.legacyFlatPrompts`

## Runtime and UI contract

- `resolvePresetCompatRuntime()` is the source of `fieldStatuses` and `providerControlIntents`
- `prompt-assembly.ts` is the canonical rendering layer
- `/api/rewrite` adds `contextWindow` and `streamPolicy`
- `PresetCompatPresetEditor` previews `fieldStatuses`, selected `providerControlIntents`, and scoped reset state
- internal prompt-rule property names that stay visible in storage and tests include `injectionPosition`, `injectionDepth`, `injectionTrigger`, and `forbidOverrides`

## Legacy flat prompt aliases and exclusions

- `main_prompt`, `nsfw_prompt`, and `jailbreak_prompt` are imported into canonical `promptRules[]` only when structured `prompts[]` are absent.
- The original flat keys are still preserved in `passthrough.root` and exported back verbatim.
- `post_history` stays a root passthrough field. It is not rewritten into `post_history_instructions`.
- Account reset, settings reset, snapshot reset, and full-user reset are not implemented here.
- `presetCompatSessionState` remains tiny and flat. It records phase and reset state only, not full chat history persistence.
- Analytical surfaces remain fail-closed, including `future_jump_bridge`, `what_if_delta_extraction`, `knowledge_extraction`, and `embeddings`.
